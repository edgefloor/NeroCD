PR 1

Bcrypt-only Local User passwords

Auth

Purpose. Remove unsalted SHA-256 password verification for Local Users and replace it with bcrypt-only verification.

  • Add internal/auth.HashPassword and internal/auth.VerifyPassword.
  • Use bcrypt.DefaultCost and a bcrypt: prefix.
  • Update memory and PostgreSQL seed users for admin and viewer.
  • Reject sha256: and unknown password hash prefixes for Local User login.
  • Document golang.org/x/crypto in the dependency policy.
Review focus
Auth behavior, seed compatibility, dependency policy
Verification
go test ./..., session API tests, smoke
PR 2

Rate limit sensitive routes

Security

Purpose. Add first in-process rate limiting for routes where repetition creates security or control-plane pressure.

  • Protect session creation, runner registration, runner claim polling, and high-impact mutations.
  • Return stable JSON error envelopes with HTTP 429 and code rate_limited.
  • Add contract coverage for the error code.
  • Keep distributed rate limiting out of scope until deployment topology is real.
Review focus
Limit keys, reset semantics, test determinism
Verification
API tests and contract check
PR 3

Validation and denial-path coverage

Tests

Purpose. Make current behavior harder to regress before adding more enterprise features.

  • Cover membership role validation and forbidden membership changes.
  • Cover template, run-spec, workflow, approval, runner-token, and artifact validation failures.
  • Prefer service and API tests over broad UI tests for this slice.
  • Keep product behavior unchanged except where tests expose a clear bug.
Review focus
Coverage quality and stable failure assertions
Verification

PR 4

Run-log follow mode

UI

Purpose. Make the terminal log dialog feel like an operator console rather than a static snapshot.

  • Add polling and follow controls around focused run logs.
  • Show terminal state clearly: queued, running, succeeded, failed, canceled, waiting approval.
  • Add explicit permission and fetch-error states.
  • Cover view-model behavior with frontend unit tests.
Review focus
Operator clarity and mobile fit
Verification

PR 5

Restore drill automation

Ops

Purpose. Turn PostgreSQL backup/restore documentation into a repeatable operator check.

  • Add a script that backs up, restores into a clean database, and runs migrations.
  • Gate it behind an explicit database URL so local development remains light.
  • Document how CI or release jobs should invoke it.
  • Keep release signing and publishing out of scope.
Review focus
Database isolation and repeatability
Verification
PostgreSQL integration environment
PR 6

Frontend route contract drift guard

Contract

Purpose. Catch undocumented frontend API usage without forcing a full generated client rewrite.

  • Extend contract validation to detect frontend API paths and methods.
  • Fail when a route used by the WebUI is missing from openapi.yaml.
  • Keep handwritten TypeScript types for now.
  • Revisit generated clients after route drift is guarded.
Review focus

Verification
